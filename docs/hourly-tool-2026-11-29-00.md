# 每小时工具开发记录：Base32 编码解码器

任务时段：2026-11-29-00（Asia/Shanghai）

## 工具与用途

- 名称：Base32 编码解码器（Base32 Encoder / Decoder）。
- 路由：`/tools/base32-encoder-decoder`；中文：`/zh/tools/base32-encoder-decoder`。
- 初始 worktree 干净，没有未完成的新工具。已阅读 CLAUDE.md、README.md、模块约定、完整工具目录、最近八次 Git 更新、最近时段开发记录及 `docs/api-network-deployment.md`。现有 Base64、十六进制、二进制转换和 TOTP 工具没有提供通用的双向 Base32 转换；本次仅新增这一工具。
- 用于检查 Base32 数据、调试认证密钥的字节表示、与采用 Base32hex 的协议交换数据。全部运算在浏览器中执行，无新依赖、外部账号、付费 API 或后台服务。
- 支持 RFC 4648 Base32（A–Z、2–7）及 Base32hex（0–9、A–V）；选择编码或解码，以及 UTF-8 文本或十六进制字节表示。字节表示在编码时指定输入格式，在解码时指定输出格式。
- 提供可选编码填充、匹配当前选项的示例、清空、字节数、复制和文本文件下载。下载名为 `base32.txt`、`decoded.txt` 或 `decoded.hex.txt`。编辑输入或切换选项会移除旧结果和复制反馈；清空恢复默认选项并聚焦输入。错误通过 aria-invalid、aria-describedby 和 alert 与输入关联，并聚焦输入。

## 实现与边界

- `src/lib/base32.ts` 提供纯字节编解码及页面转换函数；复用 TextEncoder 和严格模式 TextDecoder。用有限位缓冲区转换，逐步清除已处理位。
- 解码接受大小写、ASCII 空白、完整填充或完全不带填充。拒绝错误字母表、非法长度、填充位置/数量错误及非零尾部位，不对含糊字符做隐式替换。
- 仅忽略 ASCII 的空格、制表符、换行、回车、垂直制表符和换页符；非 ASCII 空白不被悄悄丢弃。
- 十六进制输入忽略上述 ASCII 空白后，须为完整字节对；拒绝 0x 前缀、逗号等其他分隔符。十六进制输出为小写连续字节对，可检查任意二进制数据。
- 文本编码保留输入空白，拒绝未配对 UTF-16 代理项，避免 TextEncoder 静默替换。文本解码拒绝无效 UTF-8，包括过长编码、代理项、超过 U+10FFFF 的序列及截断序列；开头的 UTF-8 BOM 保留为 U+FEFF，支持往返。
- 页面每次最多接受 100,000 个 UTF-16 代码单元，在移除空白前检查；编码结果最多为 480,000 个 Base32 字符，十六进制解码结果最多为 125,000 字符。低层字节函数允许空字节序列，页面要求非空数据；纯空白文本可以编码。
- 仅支持 RFC 4648，不支持 Crockford Base32，也不提供加密。文件下载保存展示的文本或十六进制字符串，不导出原始二进制文件。
- 复用 Workbench、Panel、Field、Output 和原有 Vite 页面发现机制；登记文本分类、搜索别名及相关工具。12 种语言均补齐界面、错误、名称、描述和 SEO 元数据；现有字典合并、SEO 生成和站点地图逻辑自动收录。
- README.md 与 CLAUDE.md 的工具数更新为 88（包括隐藏项），12 种语言各 90 页，总计 1080 页。

## 检查记录

新增 56 项核心测试、3 项页面交互测试，既有页面发现测试额外覆盖新页面。核心测试使用 RFC 4648 第 10 节的两套全部固定向量；固定种子 300 组随机字节分别验证两种字母表和两种填充方式；所有 256 个单字节值与独立的位串编码算法比较。还覆盖大小写、ASCII 空白、Unicode/BOM/空字节、无效 UTF-8、十六进制、非法字符、长度、填充、尾部位、孤立代理项和输入精确上下界。页面测试覆盖例子与选项、结果失效、错误关联与聚焦、清空、复制成功与失败、复制反馈重置。
